Multi-provider sign-in

LIVE AUTH CONVERSION ECOMMERCE

What it is

An interactive HTML/CSS/JS prototype redesigning GearLaunch's seller login flow — built from screenshots and a live walkthrough of the existing product, no source code access required.

The problem

GearLaunch sellers had exactly one way into their store dashboard: a Google account. Anyone without a Gmail login hit a hard wall at the front door, before ever seeing the product — a straightforward source of signup drop-off.

The solution

A redesigned sign-in screen offering four entry points — Google, Facebook, Apple, and email/password — while preserving GearLaunch's existing visual identity (teal brand color, dark dashboard chrome, product photography motif). Each provider button opens a realistic mock authenticator window modeled on that platform's actual UI, so the flow reads as a true login rather than a placeholder. Successful auth via any method lands the user on a faithful replica of the real GearLaunch dashboard.

Why it matters

Every additional identity provider is a common, low-risk lever for reducing signup abandonment — sellers authenticate with whatever account they already trust, instead of being forced to create or remember a new one. The prototype makes that case tangible and clickable rather than theoretical, which is what makes it useful in a stakeholder conversation.

How it was built

Built entirely through conversational iteration with Claude: starting from screenshots of the current login and dashboard screens plus plain-English direction, refined over several rounds of hands-on feedback (mock auth windows instead of a bare redirect, matching the real dashboard exactly, fixing a CSS bug that kept the login screen from properly hiding). Delivered as a single self-contained HTML file, shareable via GitHub Pages or opened locally — no build tooling required.

Skills demonstrated

Product problem framing, conversion-focused UX thinking, rapid AI-assisted prototyping, and iterative QA/debugging through a live feedback loop.

KPI Framework

How I'd Measure Success

This prototype was never shipped, so there's no before/after data to report. Here's the framework I'd use to validate it if it were.

Login success rate

Successful authentication attempts ÷ total attempts, tracked overall and by provider (Google, Facebook, Apple, email/password) — confirms the new options actually work reliably, not just exist.

Login method mix

The % split of logins across the four providers once sellers had a choice — directly validates the original hypothesis that sellers without Gmail were being forced through a wall.

Account creation success rate

% of started signups that complete account creation, before vs. after — the core conversion metric the whole prototype exists to move.

Signup abandonment at the auth wall

% of visitors who reached the sign-in screen and left without creating an account, before vs. after — the most direct proof of the original problem statement.

Time-to-first-successful-login

Median time from landing on the sign-in screen to being authenticated — confirms more options don't slow people down with choice overload.

Password-reset request volume

Reset request volume isolated to the email/password path — a friction proxy for the one method that isn't a one-click OAuth flow.
